# Ход работы над проектом

**Тема 18. University FAQ Retrieval Chatbot** — итоговый проект по дисциплине «Programming for Data Analysis and Database».

Репозиторий: https://github.com/zhankarimzhan/endterm_programming_ada0226_topic_18

## Суть проекта

Чат-бот для абитуриентов Astana IT University. Пользователь пишет вопрос своими словами, бот находит в базе FAQ самый похожий вопрос и выдаёт готовый ответ. Бот ничего не генерирует — он **ищет** среди готовых пар «вопрос — ответ».

Главный вопрос проекта: какой способ поиска лучше находит нужный ответ — простое совпадение слов (baseline), BoW / TF-IDF или смысловые эмбеддинги, и чем приходится платить за качество (время, память).

## Данные

- Датасет: [AITU Admissions Guide Dataset](https://huggingface.co/datasets/Arailym-tleubayeva/AITUAdmissionsGuideDataset) (Hugging Face, файл `QA_addmissionAitu.csv`).
- Колонки: `questions`, `answers`, `classes`. Язык — русский.
- Статья, на которой основан датасет (для ссылки в отчёте):
  A. Tleubayeva et al., "Systemic approach to optimizing natural language processing technologies in Astana IT University's admissions process," IEEE SIST 2024, pp. 520–525, doi: 10.1109/SIST61555.2024.10629481.
- Тема 18 входит в список исключений по объёму данных (не нужно 500 тыс. строк).

### Найденные проблемы данных (для аудита в отчёте)

| Проблема | Значение |
|---|---|
| Строк в исходных данных | 608 |
| Точные дубликаты (вопрос + ответ) | 29 |
| Один вопрос — разные ответы (противоречия) | 18 вопросов |
| Строки без «?» (описания курсов, а не вопросы) | 47 |
| Разных меток `classes` | 422, из них 346 встречаются по одному разу |
| Один ответ на вопросы про разные специальности | например, «Проходной балл для Computer Science?» и «…для Media Technologies?» |
| Строка-копия заголовка CSV внутри данных | 1 (`questions \| answers \| classes`) — нашлась, когда embeddings выдали её как ответ |
| Карточка датасета не совпадает с данными | заявлено ~700+ записей на казахском и русском, на деле 608 почти только на русском; лицензия указана то CC BY 4.0, то CC BY-NC 4.0 |

### Что полезного есть в данных

- **8 групп, 35 вопросов** с разными формулировками и одним ответом — готовые перефразы для тестового набора (~25 тестовых вопросов).
- Колонка `classes` — после сведения в 8–10 категорий пригодится для confusion matrix и SQL-запросов по категориям.

## Что сделано

### 1. PostgreSQL в Docker
- `docker-compose.yml`: PostgreSQL 16, порт **5433** (5432 на этой машине занят другим проектом), данные в томе `pgdata`.
- Параметры подключения — в `.env` (не в git), шаблон — `.env.example`.
- `sql/init/01_schema.sql` — схема создаётся автоматически при первом запуске контейнера.

### 2. Схема базы (7 таблиц)

| Таблица | Назначение |
|---|---|
| `categories` | категории вопросов (заполним после сведения меток) |
| `faq` | вопросы, ответы, исходная метка, категория |
| `test_queries` | тестовые вопросы и id правильного FAQ |
| `methods` | методы поиска (`pg_trgm`, позже baseline / bow / tfidf / embeddings) |
| `runs` | запуски оценки метода: P@1, P@3, MRR, время, память |
| `predictions` | топ-k ответов метода на каждый тестовый вопрос |
| `chat_log` | история вопросов пользователей (без данных о пользователе) |

### 3. Модули

| Файл | Что делает |
|---|---|
| `database.py` | подключение к PostgreSQL (`get_engine`, `check_connection`, `run_query`, `save_dataframe`, `list_tables`) |
| `data_loader.py` | скачивание CSV, очистка, сохранение в `data/` и в таблицу `faq` |
| `preprocessing.py` | токенизация, стоп-слова, стемминг, лемматизация |
| `methods/` | 5 методов поиска, каждый в своём файле (см. раздел 6) |
| `search.py` | подготовка всех методов по FAQ из базы, запись истории в `chat_log` |
| `bot.py` | Telegram-бот: `/start`, `/method` (выбор метода), ответ на любой текст |

### 4. Очистка данных (`data_loader.py`)
- нормализация пробелов, удаление пустых строк;
- удаление точных дубликатов;
- для вопросов с разными ответами оставляется **самый полный (длинный) ответ**;
- удаление строки-копии заголовка CSV;
- итог: **608 → 556** записей.

### 5. Первый метод поиска — `pg_trgm` (средствами PostgreSQL)
Сходство по триграммам символов: устойчиво к опечаткам и написанию «аиту» / «AITU».

| Запрос | Найдено | |
|---|---|---|
| как поступить в аиту | Что нужно сдать чтобы поступить в АИТУ? (0.81) | ✓ |
| какие предметы ент для информационной безопасности | Какие предметы для Информационной безопасности? (0.92) | ✓ |
| сколько стоит обучение | Сколько стоит проживание в общежитии? (0.59) | ✗ |

Третий пример — слабое место символьного сходства (совпадает «сколько стоит», а смысл другой). Это пример для анализа ошибок; такие случаи должны исправлять эмбеддинги.

### 6. Пять методов поиска — каждый в своём файле (`methods/`)

Все методы реализуют общий интерфейс `SimilarityMethod` (`methods/base.py`): `fit()` строит индекс по вопросам FAQ, `scores()` возвращает сходство запроса с каждым вопросом, `search()` — топ-k с ответами.

| Файл | Метод | Как работает | Предобработка | Порог |
|---|---|---|---|---|
| `methods/rule_based.py` | **Rule-based (baseline)** | правила замены синонимов (аиту → aitu, общага → общежитие, цена → стоимость…) + доля общих слов (Жаккар) | стемминг | 0.15 |
| `methods/bow.py` | **Bag of Words** | `CountVectorizer` + косинусное сходство | стемминг | 0.3 |
| `methods/tfidf.py` | **TF-IDF** | `TfidfVectorizer` (слова + биграммы, sublinear tf) + косинусное сходство | стемминг | 0.3 |
| `methods/embeddings.py` | **Embeddings** | `paraphrase-multilingual-MiniLM-L12-v2` (sentence-transformers), косинусное сходство векторов | нет (исходный текст) | 0.5 |
| `methods/pg_trgm.py` | **pg_trgm** (доп. метод) | `word_similarity` по триграммам в PostgreSQL | нижний регистр | 0.3 |

`preprocessing.py` — общая предобработка: токенизация, стоп-слова NLTK (вопросительные слова «как», «где», «сколько» сохраняются), стемминг Snowball и лемматизация pymorphy3 (переключается параметром `mode`). Данные NLTK хранятся в `nltk_data/` проекта: NLTK 3.10 не читает каталоги, доступные на запись другим пользователям.

`search.py` — загружает FAQ из базы, готовит все методы (`build_methods`), регистрирует их в таблице `methods` и пишет историю в `chat_log` с указанием метода.

Первое сравнение на трёх запросах (лучший ответ каждого метода):

| Запрос | Rule-based | BoW | TF-IDF | Embeddings | pg_trgm |
|---|---|---|---|---|---|
| как поступить в аиту | ✓ «Как поступить в AITU…» | ✓ | ✓ | ≈ «Что нужно сдать чтобы поступить в АИТУ?» | ≈ то же |
| сколько стоит обучение | ✗ проживание | ✗ проживание | ✗ проживание | ✓ «Какова стоимость обучения в университете?» | ✗ проживание |
| есть ли общага | ✓ «Есть ли у вас общежитие?» (правило) | ✗ ничего | ✗ ничего | ✗ (мусорная строка — удалена) | ✓ «Есть ли общежитие в AITU?» |

Каждый метод ошибается по-своему — поэтому нужен тестовый набор и метрики (P@k, MRR), а не 3 примера.

### 7. Telegram-бот с выбором метода

Бот: https://t.me/aitufaqada02progbot

- `/start` — инструкция; `/method` — кнопки выбора метода (текущий отмечен ✅), выбор запоминается для каждого пользователя;
- по умолчанию — TF-IDF; в конце ответа указан метод и сходство;
- у каждого метода свой порог «не нашёл»;
- все методы готовятся один раз при запуске (embeddings ≈ 7 с из кэша, первый раз — скачивание модели ~470 МБ).

## Как запустить

```bash
cp .env.example .env          # вписать пароль базы и TELEGRAM_BOT_TOKEN
docker-compose up -d          # поднять PostgreSQL
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python data_loader.py   # загрузить FAQ в базу
.venv/bin/python search.py        # проверить поиск
.venv/bin/python bot.py           # запустить Telegram-бота
```

Если схему меняли: `docker-compose down -v && docker-compose up -d` (скрипты из `sql/init/` выполняются только на пустой базе).
